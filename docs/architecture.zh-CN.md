# 架构与设计

## 研究候选是数据

`CandidateSpecV5` 保存表达式、方向、字段、频率、父代和协议哈希。结构化角色输出经过 JSON schema 和类型校验，再进入确定性裁决。执行器只接受算子注册表中的 DSL 调用，不对模型输出使用 Python `eval`。

调用账本记录幂等操作、预算预留、成功或失败。若请求是否抵达服务端无法判断，会保留不确定状态，避免无条件重试造成重复调用。精确回放将请求身份和响应绑定。

## 数据时间与计算

数据契约区分观察时间、可知时间和版本。`FactorDataView` 把股票身份历史与信号当日的可用范围分开；`FactorEngine` 要求公式绑定快照、字段、算子版本及安全契约。横截面排名和条件表达式都要受股票范围约束，缺失数据保持缺失。

标签通过独立的前向收益与执行时点代码生成，不能作为公式输入。正式评估模块支持时间切分和验证，组合与成本模块处理头寸约束、换手及执行影响。示例使用独立的描述性诊断模块，不把很小的合成样本当成正式推断。

## 批次与恢复

V5 控制层维护候选状态、谱系、工件、评估尝试和终止条件。SQLite 和内容寻址工件支持断点恢复；恢复必须核对原协议与输入身份。多代搜索的反馈经过限定词汇转换，外部样本外信息不能进入该循环。

原研究还使用供应商专用 L2 面板生产器及共享输入的批量重算执行器。这些依赖本地授权数据和研究契约，留在私有归档中。公开目录的调度模块与离线测试可以用于后续适配，不承诺直接运行某个供应商的历史数据。

## 交付与身份

公式、数据、代码、指标和最终值需要能相互追溯。平台上传通常只含值文件；最终研究交付还要包含生成代码、必要特征面板、冻结定义及参考值。公开演示以 `manifest.json` 验证文件完整性；清单证明字节一致，不证明研究方法正确或成绩有效。
