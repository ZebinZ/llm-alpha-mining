# 架构与研究设计

[English](architecture.md) | **简体中文** · [README](../README.zh-CN.md)

## 候选是数据，而不是可执行的模型输出

`mining/` 负责候选发现和搜索批次状态。`CandidateSpec` 记录表达式、方向、输入字段、频率、父因子和协议哈希。LLM 角色返回经过结构校验的对象，由确定性的评审逻辑执行决策，包括风险否决。DSL 遍历允许的语法树并调用已注册算子，不提供对模型输出执行 Python `eval` 的入口。

`research/` 将已接受的候选绑定到数据快照、证券契约、频率、预处理规则和算子注册表。`factor_spec_from_candidate` 明确承担这一转换。一个看似合理的公式本身，还不是可执行的研究定义。

## 时点语义

观测时间、可用时间和数据版本分别记录。`FactorDataView` 区分证券身份历史与信号时点可参与交易的范围。股票即使不在当天的截面中，其历史观测仍可能用于滚动窗口；非股票证券不能影响股票的截面排名。未来收益由独立标签模块生成，不能成为因子输入。

缺失观测和不完整的预热窗口保持缺失。缺失值不自动等于经济意义上的零。可用性契约和时间验证是必要控制，但不能证明外部数据源实际满足了其声明。

## 原始面板修正带来的研究经验

原始研究曾需要修正 snapshot 面板，并重新计算依赖该面板的因子。方法上的关键是区分没有更新与有效零值，保留真实异常检查，不能仅为提高覆盖率而放宽历史要求。输入面板修正后，股票覆盖、排名、收益诊断和相关性都可能变化，因此已有候选必须重新评估并进行相关性筛选。

公开版保留相关的身份、掩码和计算契约。授权 Level 2 数据、供应商专用修复运行器和实际因子目录保存在私有研究归档中。仅凭本仓库无法复现那次私有面板重建。

## 评估与筛选

标签、时间划分、因子指标、组合构建、成本和执行分别实现。评估前应冻结预测周期、交易时点、股票范围和成本假设。显著性模块可以评估已冻结的候选集合并进行多重检验修正。这些检查服务于研究协议；测试通过或搜索大量公式都不能证明预测能力。

默认示例只计算描述性相关性和覆盖率。正式时间评估、回测和候选集合显著性有专门的测试。外部样本外结果必须隔离在迭代搜索反馈之外。

## 可恢复执行

`mining/orchestration/` 维护候选状态、来源关系、评估尝试、停止条件和 SQLite 持久化。代际执行器记录阶段检查点，并在恢复时核验协议和文件身份。共享内容缓存依据计算输入识别结果，而不是依靠可能被覆盖的文件名。

结构化 LLM 调用带有预算、请求身份和调用账本。无法确认服务端是否收到请求的网络失败会保留为不确定状态，不会直接重复调用。精确回放需要匹配请求身份。真实模型传输是可选功能；默认示例注入预设响应，不进行网络调用。

## 包结构与文件身份

公开 API 统一使用 `llm_alpha_mining` 命名空间。`mining` 包含发现和执行，`research` 包含科学计算，`demo` 组合成小型可复现示例。测试按组件命名，不再使用项目阶段编号。

部分序列化格式保留 `/v5` 等后缀，带版本的算子语义也保留用于回放。它们标识数据格式，并不意味着保留多套源码。若在不更新身份的情况下修改语义，哈希就会失去准确含义。

研究文件应连接表达式、数据、指标和信号值。示例通过 SHA-256 清单核验文件。哈希相同只能证明字节完整性，不能证明方法正确或投资表现有效。
