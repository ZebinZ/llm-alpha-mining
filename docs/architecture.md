# Architecture and design

**English** | [简体中文](architecture.zh-CN.md) · [Back to README](../README.md)

## Research candidates are data

`CandidateSpecV5` records the expression, direction, fields, frequency, parents, and protocol hash. Structured role outputs pass JSON schema and type validation before deterministic adjudication. The executor accepts only DSL calls from the operator registry; it does not use Python `eval` on model output.

The call ledger records idempotent operations, budget reservations, and success or failure. If it is unclear whether a request reached the provider, that uncertainty is retained instead of triggering an unconditional retry and a possible duplicate call. Exact replay binds responses to request identities.

## Data time and computation

Data contracts distinguish observation time, availability time, and version. `FactorDataView` separates instrument identity history from the universe available at signal time. `FactorEngine` requires formulas to be bound to a snapshot, fields, operator versions, and a safety contract. Cross-sectional ranks and conditional expressions respect the stock universe; missing data remains missing.

Labels are generated by separate forward-return and execution-timing code and cannot be formula inputs. Formal evaluation modules support temporal splits and validation. Portfolio and cost modules handle position constraints, turnover, and execution effects. The demo uses a separate descriptive diagnostic module and does not treat a small synthetic sample as formal statistical evidence.

## Batches and recovery

The V5 control layer maintains candidate states, lineage, artifacts, evaluation attempts, and stopping conditions. SQLite and artifacts identified by their content support checkpoint recovery. Recovery checks the original protocol and input identities. Feedback for multigeneration search is converted through a restricted vocabulary; external out-of-sample information must not enter that loop.

The original research also used vendor-specific Level 2 (L2) panel builders and bulk recomputation runners with shared inputs. Those depend on privately held licensed data and research contracts, so they remain in the private archive. The public orchestration modules and offline tests provide a basis for further integration, but do not promise immediate compatibility with a particular vendor's historical data.

## Deliverables and identity

Formulas, data, code, metrics, and final values should be traceable to one another. A platform upload typically contains only signal values; a final research delivery also needs generation code, required feature panels, frozen definitions, and reference values. The public demo verifies artifact integrity with `manifest.json`. Matching hashes establish byte integrity, not methodological correctness or investment performance.
